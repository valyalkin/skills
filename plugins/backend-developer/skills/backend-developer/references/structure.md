# Project structure

A working version of everything below is in `../assets/example/` — copy from it.

```
build.gradle.kts              # one place for every plugin and dependency
settings.gradle.kts
gradle/libs.versions.toml     # the version catalogue: all versions, nothing hardcoded elsewhere
gradle.properties             # Gradle/JVM switches only
.editorconfig                 # ktlint's configuration lives here, not in the build file
detekt.yml                    # deltas from detekt's defaults, each with a reason
compose.yaml                  # local dependencies, started by bootRun
githooks/pre-commit           # installed into .git/hooks by the build
contracts/api.yaml            # GENERATED by OpenApiExportIT, committed; the frontend's input
src/main/kotlin/com/example/<service>/
  Application.kt
  config/
    SecurityConfig.kt         # resource server, entry points that emit ProblemDetail
    OpenApiConfig.kt          # the OpenAPI bean
    JacksonConfig.kt          # JSON rules the error contract depends on
    RestClientConfig.kt       # outbound clients, with explicit timeouts
    RequestIdFilter.kt        # traceId in MDC, response header and problem body
    ClockConfig.kt            # time as an injected dependency
    <Service>Properties.kt    # @ConfigurationProperties, constructor-bound, @Validated
  controller/
    <Thing>Controller.kt
  dto/
    Create<Thing>Request.kt
    <Thing>Response.kt
    PageResponse.kt           # the service's own page envelope, not Spring Data's Page
    <Thing>Mappings.kt        # model -> response, request -> command
  model/
    <Thing>.kt                # immutable, annotation-free
    <Thing>Status.kt
  repository/
    <Thing>Entity.kt          # @Entity: mutable, as Hibernate requires
    <Thing>Repository.kt      # JpaRepository
    <Thing>Mappings.kt        # entity <-> model
  error/
    ErrorCode.kt              # the error catalogue: status + type URN + title
    BusinessException.kt      # base (400) + NotFound (404) + Duplicate (409) + Unprocessable (422)
    SystemException.kt        # 5xx
    FieldViolation.kt         # one entry of the `errors` array
    ViolationExtractor.kt     # framework failure -> FieldViolation
    ProblemDetailFactory.kt   # the one place a problem response is built
    GlobalExceptionHandler.kt # @RestControllerAdvice
    ProblemErrorController.kt # container error dispatches, which the advice cannot see
    RequestId.kt
  service/
    <Thing>Service.kt
    <Dependency>Client.kt     # outbound call, wrapping failures in SystemException
src/main/resources/
  application.yaml
  application-local.yaml
  db/migration/V1__*.sql
src/test/kotlin/com/example/<service>/
  support/AbstractIntegrationTest.kt   # one Postgres and one WireMock for the whole suite
  support/JwtTestTokens.kt             # real signed tokens + the JWKS WireMock serves
  <layer>/...Test.kt                   # unit tests, no Spring context
  <layer>/...IT.kt                     # integration tests, full context
src/test/resources/application-test.yaml
```

## Why `model` and the entity are different types

`model/` is the domain: immutable, `val` only, no annotations. `repository/` holds the JPA shape:
mutable, open, annotated. The mapping between them is three lines.

It buys two things. The service is unit-testable with a mocked repository and no Hibernate, no
database and no Spring context — which is why the example's `InvoiceServiceTest` runs in
milliseconds. And a lazily-loaded entity can never escape into a response, so
`LazyInitializationException` at the controller edge stops being possible.

Both live next to the repository rather than in an `entity/` package of their own, so everything
Hibernate-aware is in exactly one place. If a class outside `repository/` imports
`jakarta.persistence`, something has gone wrong.

## Naming

- Files: PascalCase after the primary type (`InvoiceService.kt`). Packages: lowercase, singular
  (`controller`, not `controllers`).
- Entities end in `Entity`, requests in `Request`, responses in `Response`. The domain type gets
  the bare name: `Invoice`.
- Integration tests end in `IT`, unit tests in `Test`. That distinction is what lets a reader (and
  a CI split) tell a 20ms test from one that needs Docker.
- Test names are sentences in backticks: ``fun `pay refuses an already paid invoice` ()``.
- Error codes are `SCREAMING_SNAKE` enum constants with a `urn:problem:<service>:<kebab>` type.

## Deliberately absent

- No `util/` or `common/` package. A helper belongs beside its one caller, or it is a domain
  concept that deserves a name.
- No `mapper/` package and no MapStruct: extension functions beside the type that may see both
  sides are shorter and need no code generation.
- No `manager/`, `helper/` or `impl/`. A service is a class; an interface with exactly one
  implementation is indirection with no reader.
- No `ResponseEntity`, anywhere.
- No templates, static assets or view resolvers — the frontend is a separate service.

## Worked example: adding a "customers" feature

1. `db/migration/V3__create_customers.sql` — new table, additive.
2. `repository/CustomerEntity.kt` + `CustomerRepository.kt` + `CustomerMappings.kt`.
3. `model/Customer.kt` — immutable.
4. `service/CustomerService.kt` — `@Transactional(readOnly = true)` at class level, `@PreAuthorize`
   per method, `NotFoundException(ErrorCode.CUSTOMER_NOT_FOUND, "Customer $id was not found")`.
5. `error/ErrorCode.kt` — add `CUSTOMER_NOT_FOUND` with its own type URN.
6. `dto/CustomerResponse.kt` + `CustomerMappings.kt`.
7. `controller/CustomerController.kt` — `@Tag`, `@Operation`, `@ApiResponse` per outcome.
8. Tests: `CustomerServiceTest` (MockK), `CustomerControllerIT` (RestTestClient), and an entry in
   `GlobalExceptionHandlerIT` for each new error shape.
9. `./gradlew check`, then commit the regenerated `contracts/api.yaml`.
